本文档约束 QS-0002 引入的 UI 变更：**主页新增手动输入卡，将分类 Chip 行从剪切板卡内部上移到顶层共享位置**。其他规范（色彩、字体、圆角、设置页、对话框、通知）沿用项目级 [`docs/UI.md`](../../UI.md)，本文档不再重复。

---

## 一、变更摘要

| 区域 | v1.1 现状 | v1.2 变更 |
|------|----------|----------|
| 剪切板内容卡 | 卡内含 Chip 行 + 保存按钮 | 卡内**移除 Chip 行**，仅保留预览 + 保存按钮 |
| 分类 Chip 行 | 嵌入剪切板卡 | **抽出并上移到主页最上方**（设置按钮下方），独立区块，剪切板卡与输入卡共用 |
| 手动输入卡 | 不存在 | **新增**：多行 TextField + 保存按钮，与剪切板卡对仗 |
| 清空文件按钮 | 主页底部，全宽 | 不变 |
| 设置页 | 不变 | 不变 |
| 通知 | 不变 | 不变 |

## 三、组件规格

### 3.1 共享分类 Chip 行（顶层独立区块，v1.2 位置变更）

| 元素 | 规格 |
|------|------|
| 容器 | 主页主轴布局直接子项（不再嵌入卡片） |
| 位置 | 设置按钮下方 12dp，剪切板卡上方 12dp（即页面所有保存来源的**最上方**） |
| 上方 label | `labelSmall` 11sp / 500，OnSurfaceVariant，文案「分类（可选）」，左对齐 |
| Chip 行 | `LazyRow` 横向滚动，`horizontalArrangement = spacedBy(6.dp)` |
| 行为 | 与 v1.1 完全一致：选中切换、点击「＋ 新增」弹对话框、空列表时只显 ＋ |

> Chip 行抽离并上移后，剪切板卡和手动输入卡内的保存按钮在 v1.2 中**仍然读取同一个 `selectedCategory`**，行为对用户透明。把 Chip 行放在最上方，让用户决策路径线性化：先选分类 → 再选保存来源 → 点保存。

### 3.2 手动输入卡（v1.2 新增）

| 元素 | 规格 |
|------|------|
| 容器 | Card，圆角 12dp，宽全屏减 32dp（左右 16dp 边距），内边距 12dp |
| 背景 | `Surface` (`#FFFBFE`)，描边 `Outline` 1dp（与剪切板卡的 PrimaryContainer 视觉分层） |
| 标题 | `labelSmall` 11sp / 500，OnSurfaceVariant，文案「手动输入」 |
| 输入框 | `OutlinedTextField`：`minLines=3`、`maxLines=6`、超出可滚动；`textStyle = bodyMedium`；`placeholder = "在此输入要保存的文字"`；`shape = RoundedCornerShape(8dp)`；颜色使用 `OutlinedTextFieldDefaults.colors()` 的默认 Primary 强调色 |
| 输入框上下间距 | 标题底 4dp → 输入框；输入框底 10dp → 保存按钮 |
| 保存按钮 | FilledButton，`保存到文件 ▶`，宽 120dp / 高 36dp，胶囊（radius 18dp），右对齐；状态见 §3.3 |
| imeAction | `Default`（多行换行优先，不收起键盘） |

### 3.3 手动输入保存按钮 — 状态机

| 状态 | 触发条件 | 视觉 | 可点击 |
|------|---------|------|--------|
| **禁用** | TextField 为空 / 仅含空白字符 | Primary 12% 透明度填充，文字 38% 透明度 | ✗ |
| **可保存** | TextField 非空 | Primary 实色填充 (`#6650A4`)，白色文字 | ✓ |
| **保存中** | 点击后、IO 进行中 | 文字改为「保存中…」，颜色不变，附带 16dp `CircularProgressIndicator`（白色，左侧 6dp 间距） | ✗ |
| **保存成功后** | Result.success 返回 | 自动恢复禁用态（输入框已清空） | ✗（直至重新输入） |

### 3.4 剪切板内容卡（v1.2 微调）

| 调整项 | 描述 |
|--------|------|
| 移除元素 | 卡内 Chip 行（含「＋ 新增」） |
| 卡片高度变化 | v1.1 `~142dp` → v1.2 `~110dp`（减少 Chip 行 + 内边距 ~32dp） |
| 其他 | 标题、内容预览、保存按钮、PrimaryContainer 背景**保持不变** |

## 四、交互细节

### 4.1 输入与保存

1. 用户点击 `OutlinedTextField` → 系统键盘弹起
2. 输入字符过程中：
   - 实时启用/禁用保存按钮（依据 `text.trim().isNotEmpty()`）
   - TextField 高度随内容增长（minLines=3, maxLines=6，超出后内部滚动）
3. 点击保存按钮：
   - 按钮切换为「保存中…」并禁用
   - 收起键盘（`LocalSoftwareKeyboardController.current?.hide()`）
   - 调用 `repo.saveEntry(text, selectedCategory)`
4. 成功：
   - Snackbar「已保存」(SHORT)
   - TextField 清空，焦点保留在 TextField
   - 分类选中状态**保持不变**
5. 失败：
   - Snackbar 显示具体错误（同剪切板保存路径，§六）
   - TextField 内容**保留**
   - 焦点不强制变化

### 4.2 配置变更（旋转 / 切出 / 多窗口）

- TextField 内容通过 `rememberSaveable` 在 Bundle 中保留
- `selectedCategory` 由 DataStore 持久化，自然恢复
- 进程被强杀后输入内容**丢失**（不在范围）

### 4.3 双保存路径并存

- 用户可任意时刻点击两个保存按钮中的任一个
- 两个按钮的「保存中…」状态**独立**：剪切板保存进行中不影响手动输入按钮，反之亦然
- 一个 Snackbar 通道，新消息覆盖旧消息（沿用现有规范）

### 4.4 输入控制

| 行为 | 处理 |
|------|------|
| 输入换行符 | 完整保留，写入文件时不转义 |
| 粘贴长文本 | 不限制长度 |
| 全选 / 复制 / 剪切 | 系统默认行为，不拦截 |
| 输入法候选词 | 系统默认 |
| 自动大小写 | 关闭（`KeyboardCapitalization.None`），与"快速记录"语义一致 |

## 五、空状态与边界视觉

| 状态 | 主页表现 |
|------|---------|
| 剪切板有内容 + 已配置文件 | 剪切板卡 + Chip 行 + 输入卡（默认） |
| 剪切板为空 + 已配置文件 | "剪切板为空" 提示文字（替代剪切板卡） + Chip 行 + 输入卡 |
| 未配置文件（不论剪切板是否有） | 顶部警告卡 + 设置按钮 + 剪切板卡（如有）+ Chip 行 + 输入卡 — 输入卡保存按钮**仍可点击**，点击后由 ViewModel 弹 Snackbar 提示去设置 |
| 输入框为空 | 保存按钮禁用（视觉低对比） |
| 输入框已输入但未配置文件 | 保存按钮启用；点击后 Snackbar「请先在设置中选择保存文件」，输入**保留** |

## 六、Snackbar 反馈（QS-0002 范围）

| 场景 | 消息 | 时长 | 备注 |
|------|------|------|------|
| 手动输入保存成功 | `已保存` | SHORT | 输入框清空 |
| 手动输入未配置文件 | `请先在设置中选择保存文件` | LONG | 输入保留 |
| 手动输入权限丢失 | `文件无写入权限，请重新选择` | LONG | 输入保留 |
| 手动输入 IO 失败 | `保存失败：{message}` | LONG | 输入保留 |

> 文案与剪切板保存路径**完全一致**——用户无需区分来源。Snackbar 不区分两条路径来源。

## 七、可访问性

- TextField 有显式 `labelText = "手动输入"` 供 TalkBack 朗读（视觉 label 与 TextField label 内容一致）
- 保存按钮 `contentDescription` 在保存中态变为「保存中"」
- TextField 支持系统字体缩放至 200%，输入卡内边距随字号缩放保持可读
- 触控目标：保存按钮高度 36dp，但 ripple 区域扩展到 48dp（M3 默认）
