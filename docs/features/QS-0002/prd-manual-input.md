## 一、需求背景与用户痛点

QuickSave 当前只支持把**剪切板内容**追加到目标文件。但用户经常遇到这样的场景：

- 想直接写一句即时想法（"刚刚电话里说要 5/15 之前给报价"），目前必须先在别处打字 → 复制 → 切回 QuickSave → 保存，多此一举
- 在 QuickSave 中复盘剪切板内容时想加一句旁注（"这条要重点跟进"），现有流程无法做到
- 内容来自语音输入或键盘直接输入，从未经过剪切板

**核心承诺**：用户在 QuickSave 主页直接输入文字，一键保存到目标文件，并可选附带分类标签——与剪切板保存享有同等的文件、格式、分类基础设施。

## 二、目标用户

| 用户类型 | 典型场景 |
|---------|---------|
| 即时记录者 | 想到一件事就马上记下来，不想离开 QuickSave |
| 旁注添加者 | 在保存剪切板内容前后，希望补一段自己的说明 |
| 语音 / 输入法使用者 | 内容由输入法直接生成，不经过剪切板 |

## 三、用户故事

| # | 用户故事 | 验收条件 |
|---|---------|---------|
| US-01 | 作为用户，我希望在主页有一个**多行输入框**，可以直接输入想保存的文字。 | 主页可见一个多行 TextField，最少 3 行可见高度，超出可在框内滚动；初始为空，placeholder 提示「在此输入要保存的文字」 |
| US-02 | 作为用户，我希望输入完成后点击**保存按钮**，立即将文字按现有格式追加写入目标文件。 | 点击后将输入文字（含可选分类前缀和时间戳）追加写入目标文件；Snackbar 显示「已保存」 |
| US-03 | 作为用户，我希望保存前可以**选择一个分类标签**，与剪切板保存共用同一组分类。 | 输入框上方或下方显示与剪切板保存共用的分类 Chip 行；选中分类后保存格式带分类前缀 |
| US-04 | 作为用户，我希望保存成功后**输入框自动清空**，方便我紧接着输入下一条。 | 保存成功后 TextField 回到空状态；分类选中状态保持不变（持久化策略与现有 selectedCategory 一致） |
| US-05 | 作为用户，我希望**输入框为空（含纯空白）时无法保存**，避免误产生空记录。 | 输入框为空或仅含空白字符时，保存按钮禁用；非空时启用 |
| US-06 | 作为用户，我希望**输入内容在屏幕旋转或临时离开应用时不丢失**，但应用被杀后无需保留。 | 输入文字使用 `rememberSaveable` 在配置变更与进程重建（Bundle）期间保留；应用进程被强制结束后不要求保留 |

## 四、功能范围

### 4.1 已交付

> 本 feature 当前为规划中（v1.2 预期），尚无已交付项。

### 4.2 v1.2 计划交付

| 功能 | 描述 |
|------|------|
| 主页手动输入框 | 多行 TextField，3 行可见，超出滚动，placeholder 文案 |
| 手动输入保存按钮 | 输入非空时启用；保存成功后清空输入；与剪切板保存路径互不干扰 |
| 共享分类选择 | 与剪切板保存共用同一 Chip 行与 `selectedCategory` 持久化值 |
| 配置变更恢复 | 旋转 / 短暂切出时输入内容保留 |

### 4.3 不在本 feature 范围

- **草稿持久化跨进程**：应用被强杀或重启后输入内容**不保留**
- 输入历史 / 撤销重做
- Markdown / 富文本格式
- 多个独立输入框（如标题 + 正文）
- 语音输入按钮（依赖系统输入法即可）
- 自动保存（必须显式点击保存按钮）
- 替换或隐藏剪切板保存路径

## 五、交互流程

### 流程 A：手动输入并保存（主路径）

```
用户在 QuickSave 主页
       ↓
点击多行输入框，键盘弹起
       ↓
输入文字（实时显示字符）
       ↓
（可选）在分类 Chip 行选中或切换分类
       ↓
点击「保存」按钮（输入非空时启用）
       ↓
文字 + 时间戳（+ 分类前缀）追加写入目标文件
       ↓
Snackbar 显示「已保存」
       ↓
输入框自动清空，分类选中状态保留
```

### 流程 B：未配置目标文件即点击保存

```
用户已输入文字
       ↓
点击「保存」按钮
       ↓
Snackbar 显示「请先在设置中选择保存文件」
       ↓
输入框内容保留，便于配置后再次保存
```

### 流程 C：与剪切板保存协同

```
主页同时展示：
  ┌─ 剪切板内容卡（如有剪切板内容）── 保存按钮 ① ─┐
  ├─ 分类 Chip 行（共享） ─────────────────────────┤
  └─ 手动输入框 ── 保存按钮 ② ─────────────────────┘

用户可任选其一保存；两条路径共享分类、共享目标文件、共享 Snackbar 反馈区
保存按钮 ② 不影响剪切板内容；保存按钮 ① 不影响输入框内容
```

## 六、边界条件 & 异常处理

| 场景 | 期望行为 |
|------|---------|
| 输入为空 / 全空白 | 保存按钮禁用，不弹任何提示 |
| 未配置目标文件 | 点击保存后 Snackbar 提示「请先在设置中选择保存文件」；输入内容保留 |
| SAF 权限丢失 | Snackbar 提示「文件无写入权限，请重新选择」；输入内容保留 |
| 文件写入失败（其他 IO） | Snackbar 提示「保存失败：{错误信息}」；输入内容保留 |
| 保存成功 | Snackbar 「已保存」；输入框清空；分类选中状态保留 |
| 输入超长（如 10000+ 字符） | 不做长度限制；按现有保存格式整段写入 |
| 输入含换行符 | 完整保留换行符写入文件（与剪切板保存的换行处理一致） |
| 旋转屏幕 / 多窗口切换 | 输入内容保留；分类选中保留 |
| 进程被系统强制结束 | 输入内容**不保留**（不在范围） |
| 同时点击两个保存按钮 | 二者独立执行；UI 上保存中按钮禁用，避免重复点击 |

## 七、非功能性需求

| 项目 | 要求 |
|------|------|
| 兼容性 | 不破坏 QS-0001 已有保存格式；无分类时格式仍为 `[时间戳] 内容\n` |
| 性能 | 输入响应不卡顿；保存操作 ≤ 200ms（中端机型，IO 正常） |
| 可访问性 | TextField 支持系统字体缩放；保存按钮符合 48dp 触控目标 |
| 隐私 | 输入内容仅写入用户选定的本地文件，不上传任何网络 |

| 指标 | 目标 |
