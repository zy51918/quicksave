## 一、背景

QS-0004 交付后，iOS 版有了三个文字入口：主页剪切板保存、主页手动输入、其他 App 分享（Share Extension）。用户在真机体验后提出：**iOS 缺少 Android 悬浮窗那种「随时可用、一触即达」的常驻快捷入口**。

Android 版靠 `TYPE_APPLICATION_OVERLAY` 悬浮窗做到「任意 App 之上贴边常驻，点开即操作」。iOS 第三方 App **没有**等价公开 API，无法在别的 App 上层绘制常驻 UI。这是平台限制，不是实现工作量问题（详见 [arch-ios-port.md](../QS-0004/arch-ios-port.md) §一）。

因此本 feature 的目标不是「复刻悬浮窗」，而是在 iOS 允许的公开能力内，提供**尽可能接近的快捷入口**，降低「打开 QuickSave → 保存」的摩擦。

## 二、目标

- 让用户无需先回主屏找到 App 图标，即可在 1~2 步内进入 QuickSave 并保存文字。
- 优先落地**控制中心控件**（iOS 18+）：下拉控制中心一键触发，是全平台最接近 Android 悬浮窗「随时一键」的合规入口。
- 复用现有保存链路与分类语义，不引入第二套保存实现。
- 全部使用 App Store 合规的公开 API，不使用私有 API、不做越狱适配。

## 三、非目标

本 feature **不做**：

- 复刻 Android 悬浮窗（iOS 无公开 API，不可实现）。
- 后台剪切板轮询 / 复制即自动保存（iOS 会弹隐私提示且耗电，`arch-ios-port.md` §一 已排除）。
- 画中画（PiP）挪作悬浮窗用途（仅限视频/通话，滥用必被 App Review 拒绝）。
- 锁屏常驻富交互面板（iOS 不给第三方 App 持续占屏的自绘 UI）。
- 录音、常驻通知（沿用 QS-0004 的延期结论）。
- Android 版新增功能（本 feature 仅 iOS）。

## 四、用户故事

| # | 用户故事 | 验收条件 |
|---|---------|---------|
| US-Q01 | 作为用户，我希望**把 QuickSave 添加到控制中心**，之后下拉控制中心即可一键触发。 | 控制中心编辑页的「控制」分组中可找到 QuickSave 控件并添加；添加后控件显示于控制中心 |
| US-Q02 | 作为用户，我希望**点击控制中心控件后能立即保存当前剪切板文字**，不必先打开 App 再点保存。 | 点击控件后，剪切板非空时按当前分类与格式追加写入目标文件，并给出「已保存」结果反馈 |
| US-Q03 | 作为用户，我希望控制中心控件的**图标能反映保存是否可行**（如未配置文件时提示先配置）。 | 未配置目标文件时，控件以不可用/提示态呈现，点击后反馈「请先在设置中选择保存文件」 |
| US-Q04 | 作为用户，我希望**不想用控制中心时，也能用 Siri / 快捷指令 / 现有系统入口**打开 QuickSave。 | 现有 App Intent（`OpenQuickSaveIntent`）保持可用；Siri 短语「打开 QuickSave」可唤起 App |
| US-Q05 | 作为用户，我希望**快捷入口不破坏现有操作习惯**。 | 主页、设置页、Share Extension 行为与 QS-0004 完全一致，无回归 |
| US-Q06 | 作为用户，我希望在**不支持控制中心的系统版本上仍可使用 QuickSave**。 | iOS 16/17 设备不出现控件入口，主 App 与 Share Extension 功能完整可用，不崩溃 |

## 五、方案选型

按「与 Android 悬浮窗的接近程度」排序，本项目采用 **方案 A**，B/C 作为既有能力保留，D/E 明确排除。

| 方案 | 入口 | 快速程度 | 结论 |
|---|---|---|---|
| **A. 控制中心控件**（`ControlWidget`，iOS 18+） | 下拉控制中心 | ★★★ | **本次采用** |
| B. Siri / 快捷指令 / Spotlight | 语音或搜索 | ★★ | 已有 `OpenQuickSaveIntent`，保持 |
| C. 锁屏/主屏小组件（WidgetKit） | 桌面/锁屏点按 | ★★ | 后续可评估，本次不做 |
| D. Action Button 实体键 | 物理按键 | ★★★ | 用户设备相关，非普适；可复用同一 Intent，不单独投入 |
| E. 画中画 / 私有悬浮窗 | — | — | **排除**，违反合规约束 |

### 5.1 方案 A 的关键技术约束（待开发阶段验证）

> 以下为 PRD 层面的**需求约束**，具体 API 可行性由 `/dev` 在架构设计阶段验证并在 `arch-ios-quick-entry.md` 给出结论。

1. **系统版本门槛**：`ControlWidget` 需要 iOS 18+。低于该版本不提供入口（US-Q06）。
2. **执行时机**：控制中心控件的动作由 App Intent 承载。**意图能否在不打开 App 的情况下完成文件写入，需要开发阶段实测确认**；两种结果对应两种可接受的产品形态：
   - **形态一（静默保存）**：Intent 在后台完成写入，控制中心轻提示结果。体验最接近 Android 悬浮窗。**以此为首选目标。**
   - **形态二（打开 App 保存）**：若系统要求拉起 App 才能执行，则点击控件等效于「打开 QuickSave 并自动保存当前剪切板」，仍显著少于「找图标 → 打开 → 点保存」。
   - 无论哪种形态，US-Q02 的验收标准为「点击到保存完成之间，用户无需额外的输入或翻页操作」。
3. **进程与权限**：控件运行于扩展进程，需通过 App Group 读取目标文件 bookmark 与当前分类（已有 `group.com.ylib.quicksave`，见 [AppDependencies.swift](../../../ios/QuickSave/Support/AppDependencies.swift)）。security-scoped bookmark 在扩展进程内可用性需实测。
4. **禁用态表达**：控件需在未配置目标文件时呈现可区分的状态，具体呈现方式由 HIE 设计阶段确定。

## 六、功能范围

### 6.1 本次交付

| 功能 | 描述 |
|------|------|
| 控制中心控件 | 新增 QuickSave 控件，可添加到控制中心；提供一个「保存剪切板」主动作 |
| 保存 App Intent | 复用现有 `ClipRepository.saveEntry`，通过 App Group 读取配置；不新写保存逻辑 |
| 结果反馈 | 保存成功/失败后给出结果反馈，文案沿用 §六 边界表 |
| 降级处理 | iOS 17 及以下不显示控件入口；未配置目标文件时控件呈现不可用态并反馈引导文案 |
| 文档同步 | 更新项目级 PRD / UI / ARCH 及 feature 级文档 |

### 6.2 不在本次范围

- 锁屏/主屏小组件（WidgetKit）
- 控件内联输入文字（控制中心控件不支持富输入）
- 控件内选择分类（控件仅承载单一动作，分类沿用 App 内当前选中值）
- 多控件 / 可配置控件（用户自定义动作）
- Action Button 的专门适配与引导

## 七、交互流程

### 流程 A：控制中心一键保存（首选形态）

```
用户在其他 App 复制文字
       ↓
下拉控制中心，点击 QuickSave 控件
       ↓
读取 App Group 中的目标文件 bookmark 与 selectedCategory
       ↓
追加写入目标文件（格式同主 App）
       ↓
反馈「已保存」；用户停留在原 App
```

### 流程 B：未配置目标文件

```
下拉控制中心，点击 QuickSave 控件
       ↓
检测到未配置目标文件
       ↓
反馈「请先在设置中选择保存文件」
       ↓
（可选）用户点反馈/控件进入设置页完成配置
```

### 流程 C：Siri / 快捷指令（既有能力）

```
用户对 Siri 说「打开 QuickSave」
       ↓
QuickSaveIntent 唤起 App 主页
       ↓
用户手动选择保存来源并保存
```

## 八、边界条件 & 异常处理

| 场景 | 期望行为 |
|------|---------|
| 未配置目标文件 | 反馈「请先在设置中选择保存文件」，不写入、不崩溃 |
| 目标文件权限丢失 | 反馈「文件无写入权限，请重新选择」 |
| 剪切板为空 | 反馈「剪切板为空，请先复制文字」 |
| 文件写入失败 | 反馈「保存失败：{原因}」 |
| 控件的扩展进程无法访问 bookmark | 反馈引导文案并指向主 App；不得静默失败 |
| 系统版本 < iOS 18 | 不提供控件入口；主 App 功能不受影响 |
| 连续快速点击控件 | 写入串行、无重复记录、无文件损坏 |
| 分类在控件触发前被删除 | 按无分类格式保存（与主 App 语义一致） |

> 反馈文案与 [UI.md](../../UI.md) §6.2 iOS 反馈规范保持一致；控件形态下的反馈载体（系统提示 / 打开 App 后的 Toast）由 HIE 设计阶段确定。

## 九、非功能性需求

| 项目 | 要求 |
|------|------|
| 系统版本 | 主 App 保持 iOS 16.0+；控制中心控件按 iOS 18+ 条件提供 |
| 合规 | 仅使用公开 API；不使用私有 API、不越狱、不为绕过平台限制做规避 |
| 权限 | 不新增任何运行时权限 |
| 数据一致性 | 与主 App、Share Extension 共用同一目标文件、分类与保存格式；不引入第二套存储 |
| 依赖 | 复用现有 `ClipRepository` / `BookmarkFileDataSource` / App Group，不新增网络或第三方库 |
| 性能 | 点击控件到写入完成应无明显可感延迟；写入串行不阻塞主 App |

## 十、成功指标

| 指标 | 目标 |
|------|------|
| 快捷保存步骤 | 从「复制文字」到「保存完成」≤ 2 步（下拉控制中心 + 点击控件） |
| 相对现状改善 | 相比「找图标 → 打开 App → 点保存」减少 ≥ 2 步 |
| 可靠性 | 权限正常时写入成功率 100% |
| 回归 | 现有主页 / 设置页 / Share Extension 测试用例全部通过 |

## 十一、验收标准

- 控制中心可添加 QuickSave 控件，添加路径可达（US-Q01）。
- 点击控件后，剪切板文字按现有格式追加写入目标文件，结果为「已保存」（US-Q02）。
- 未配置目标文件时给出引导文案而非静默失败（US-Q03）。
- 现有 App Intent / Siri 入口仍然可用（US-Q04）。
- iOS 17 及以下设备不出现控件入口，主 App 与 Share Extension 功能完整（US-Q06）。
- 主页、设置页、Share Extension 无行为回归（US-Q05）。
- 保存格式、分类语义、错误映射与 Android / QS-0004 完全一致。

## 十二、风险与待决事项

| 项 | 说明 | 处理 |
|---|---|---|
| 控件内执行文件写入的可行性 | 系统是否允许控件 Intent 不拉起 App 完成写文件，需实测 | `/dev` 架构阶段验证；两种形态均可接受（§5.1） |
| security-scoped bookmark 在扩展进程的可用性 | 控件为扩展进程，bookmark 解析可能受限 | `/dev` 实测；不可用时降级为「打开 App 保存」形态或改用 App Group 内文件 |
| 最小系统版本策略 | 是否将主 App 最低版本提升到 iOS 18 以统一体验 | 本次**不提升**，保持 iOS 16+，控件按版本条件提供 |
| 反馈载体 | 控件触发后结果如何呈现（系统提示 vs 打开 App Toast） | HIE 设计阶段随 UI 文档确定 |
