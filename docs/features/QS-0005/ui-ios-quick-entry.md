## 一、范围

本文档定义 iOS 快捷入口的界面与反馈规范，覆盖三处：

| 载体 | 平台能力 | 本次交付 |
|---|---|---|
| 控制中心控件 | `ControlWidget`（iOS 18+） | **新增** |
| 设置页引导区块 | SwiftUI（主 App） | **新增** |
| Siri / 快捷指令 | `AppIntent`（已有） | 保持，不新增 UI |

不涉及主页与 Share Extension 的改动，二者行为与 QS-0004 完全一致。

## 二、设计原则

沿用项目级 §一 与 QS-0004 §二，本 feature 补充：

| 原则 | 落地 |
|---|---|
| **极简** | 控件只承载**单一动作**（保存剪切板），不做多按钮或菜单 |
| **状态可见** | 控件自身表达「可否保存」，用户点之前就能预判结果 |
| **即时反馈** | 沿用 QS-0004 `QuickSaveToast`；无法浮层时用控件自更新或 App 内 Toast |
| **零学习成本** | 控件外观用现有 `archivebox` 符号与色板，与 App 内视觉一致 |

> **平台约束**：控制中心控件不支持富 UI —— 无内联输入框、无分类选择器、无自定义弹层。控件只能呈现一个图标 + 标题，动作由 App Intent 承载。这决定了「控件内选分类」不在本 feature 范围（PRD §6.2）。

## 三、控制中心控件设计

### 3.1 基本信息

| 项目 | 值 |
|---|---|
| 显示名称 | `QuickSave` |
| 描述 | `保存剪切板文字到目标文件` |
| 控件类型 | `ControlWidgetButton`（单动作按钮） |
| 系统符号 | `archivebox` / `archivebox.fill`（与现有 `OpenQuickSaveIntent` 的 `systemImageName` 一致） |
| 主色调 | `quickSaveTealDark`（`#465511`）—— 控件 tint 落在系统浅色底上，品牌浅绿 `#C5E166` 作 tint 对比度仅 1.36:1，故取深橄榄 |

### 3.2 状态与外观

控件在控制中心有四种可呈现状态。状态由「目标文件是否已配置」决定基础形态，由「最近一次动作结果」决定瞬时形态。

| 状态 | 符号 | 标题 | 颜色 | 点击行为 |
|---|---|---|---|---|
| **就绪**（默认） | `archivebox.fill` | 保存剪切板 | `quickSaveTealDark` | 保存当前剪切板文字 |
| **未配置** | `archivebox` + 角标 `exclamationmark` | 去设置 | `quickSaveCoral` | 打开 App 并直达设置页 |
| **保存中** | 短暂过渡态 | 保存中 | `quickSaveInkSoft` | 忽略重复点击 |
| **刚成功** | `checkmark.circle.fill` | 已保存 | `quickSaveTealDark` | 约 2s 后回落到「就绪」 |
| **刚失败** | `exclamationmark.circle.fill` | 未保存 | `quickSaveCoral` | 约 3.5s 后回落；再次点击重试 |

**布局**（控制中心圆形/方形控件位）

```
┌──────────┐        ┌──────────┐
│          │        │    ⚠     │
│    ▣     │        │    ▣     │
│          │        │          │
└──────────┘        └──────────┘
  保存剪切板           去设置
   （就绪）           （未配置）
```

- 图标居中，18×18 视觉重量对齐系统控件（实际随控件位自适应放大）。
- 不添加文字标签于图标内 —— 控制中心以 system 字号渲染标题，自绘文字会与系统风格冲突。
- 「未配置」态用角标而非替换图标，保留 `archivebox` 的识别连续性。

### 3.3 交互规格

| 行为 | 规格 |
|---|---|
| 点击（就绪） | 读取 App Group 中的目标文件 bookmark 与 `selectedCategory`；追加写入；控件瞬时切到「刚成功」/「刚失败」 |
| 点击（未配置） | 打开主 App 并导航至设置页，焦点停在「保存目标文件」区块 |
| 重复点击 | 写入串行；「保存中」期间后续点击被忽略，不产生重复记录 |
| 长按 | 无自定义行为，交由系统处理（进入控制中心编辑态） |
| 分类 | 沿用主 App 当前 `selectedCategory`；控件内不提供切换 |

### 3.4 无障碍

- 控件提供 `accessibilityLabel`：就绪态「保存剪切板文字到目标文件」，未配置态「QuickSave 尚未设置保存文件，点击前往设置」。
- 结果通过控件标题变更传达（「已保存」/「未保存」），依赖 VoiceOver 的控件重读；若系统不主动播报，不额外补偿（避免在第三方 App 上下文弹出打断）。

## 四、反馈呈现规范

这是本 feature 最需要澄清的部分：**点击控件后控制中心会立即收起，用户回到原 App**，因此 Android 那种「浮在原 App 之上的 Toast」在控件触发路径下**不存在**。反馈按下表分层呈现。

### 4.1 分层反馈策略

| 层级 | 形态 | 触发条件 | 说明 |
|---|---|---|---|
| L1 | 控件自身状态变化 | 始终 | 控件重渲染为「已保存」/「未保存」，用户下拉控制中心可复查 |
| L2 | 主 App 内 Toast | 仅在 App 被拉起时 | 复用 `QuickSaveToast`，文案与 QS-0004 §3.1 完全一致 |
| L3 | 主 App 内待办提示 | 用户下次打开 App 时 | 若静默保存发生失败而用户未察觉，在主页 Toast 提示最近一次失败原因 |

> **L3 的必要性**：静默保存的最大风险是「用户以为存了，其实没存」。因此**必须**在 App Group 记录最近一次快捷保存的失败结果，用户下次进入主 App 时以 Toast 提示一次（消费即清）。

### 4.2 文案（与 QS-0004 保持一致）

| 场景 | 控件标题 | App 内 Toast |
|---|---|---|
| 保存成功 | 已保存 | 已保存 |
| 未配置目标文件 | 去设置 | 请先在设置中选择保存文件 |
| 权限丢失 | 未保存 | 文件无写入权限，请重新选择 |
| 剪切板为空 | 未保存 | 剪切板为空，请先复制文字 |
| 写入失败 | 未保存 | 保存失败：{原因} |

时长沿用 QS-0004 §3.1：成功 2.0s，失败 3.5s。

### 4.3 明确的非目标

以下反馈形态经评估**不采用**：

| 形态 | 不采用原因 |
|---|---|
| 控件触发后弹系统通知 | 需申请通知权限；为一次轻量保存打断用户不划算 |
| Live Activity / 灵动岛做临时反馈 | 需 ActivityKit 且生命周期语义不匹配（快速活动无常驻合理性）；成本远高于收益 |
| 音效 / 震动反馈 | 系统不保证在控件 Intent 内可触发；静默环境下可能打扰 |
| 打开 App 再自动返回 | 会打断用户当前上下文，比「不反馈」更差 |

## 五、设置页引导区块

用户不会自发发现「控制中心可添加控件」，因此在设置页增加一个引导区块。

### 5.1 布局

```
┌─────────────────────────────────────┐
│  ←  设置                            │
├─────────────────────────────────────┤
│  快捷入口            ← Section 头    │
│  ─────────────────────────────────  │
│                                     │
│  添加到控制中心                      │  ← 标题行
│  下拉控制中心 → 点左上「+」→          │  ← 说明，footnote/secondary
│  找到 QuickSave → 添加。             │
│                                     │
│  添加后可一键保存剪切板文字，          │  ← 价值说明
│  无需先打开 App。                     │
│                                     │
│  [ 打开控制中心 ]                    │  ← 主按钮（见 5.2）
└─────────────────────────────────────┘
```

### 5.2 「打开控制中心」按钮的取舍

iOS **没有**公开 API 能从 App 内直接跳转到控制中心，也无法以编程方式添加控件 —— 这必须由用户手动完成。

因此按钮降级为**引导**而非跳转：

| 方案 | 采用 | 理由 |
|---|---|---|
| 按钮直接跳控制中心 | ✗ | 无公开 API；私有 scheme 无法过审 |
| 按钮复制引导文案到剪切板 | ✗ | 文案短，复制反而添乱 |
| 静态图文引导（无按钮） | ✓ | 诚实、无假承诺 |
| 系统版本不符时显示说明 | ✓ | iOS 17 及以下提示「需要 iOS 18 及以上」 |

### 5.3 版本条件

| 系统版本 | 设置页「快捷入口」区块 |
|---|---|
| iOS 18+ | 显示引导图文 |
| iOS 17 及以下 | 显示 `需要 iOS 18 及以上系统才能添加控制中心控件`，不显示引导步骤 |

## 六、与 Android 悬浮窗的差异

明确记录能力落差，避免后续误判为缺陷。

| 项目 | Android 悬浮窗 | iOS 控制中心控件 | 原因 |
|---|---|---|---|
| 常驻可见 | 任意 App 上层贴边常驻 | 需下拉控制中心才可见 | iOS 无跨 App 自绘层 |
| 触发步骤 | 点把手 → 点按钮 = 2 步 | 下拉 → 点控件 = 2 步 | **持平** |
| 内联输入 | 透明输入窗可输入文字 | 无 | 控件不支持富 UI |
| 内联选分类 | 面板内可选 | 无（沿用 App 内选中值） | 控件不支持富 UI |
| 录音 | 面板内一键录音 | 无 | QS-0004 已延期录音 |
| 结果反馈 | Toast 浮在原 App 上 | 控件自更新 + App 内 Toast | 控件触发后控制中心即收起 |
| 未配置引导 | Toast 提示 | 点击直达设置页 | 控件可直接驱动导航 |

> 结论：控件在「一键保存剪切板」这一主路径上触发步数与 Android 持平，**能力落差集中在「内联输入」与「内联选分类」**，这两项依赖富 UI，iOS 不给。

## 七、测试与验证

**模拟器可验证**

- 设置页「快捷入口」区块在 iOS 18 / iOS 17 两种模拟器下的显示差异。
- iOS 17 模拟器下 App 不崩溃、主页与设置页功能完整。
- 主 App 内 Toast 文案与时长无回归。

**需真机验证（模拟器不支持控制中心控件交互）**

- 控件能否被添加到控制中心。
- 点击控件后是否在**不打开 App** 的前提下完成写入（PRD §5.1 待验证项）。
- 控件「已保存」「未保存」瞬时态的实际呈现与回落时机。
- 未配置态点击后是否正确直达设置页。
- security-scoped bookmark 在控件扩展进程内是否可解析。
- VoiceOver 下控件标签的播报内容。

**待开发阶段确认项**

> 本文档中「控件自身状态变化」（L1）与之前置依赖 —— 控件 Intent 能否在扩展进程内完成文件写入 —— 尚未实测。若实测结论为**必须打开 App**，则 §3.2 的「刚成功/刚失败」瞬时态与 §4.1 的 L1 层失效，反馈全部落到 L2（App 内 Toast），交互等效于「点击控件 → 打开 App → 自动保存并反馈」。届时需回修本文档 §3、§4 与 UI.md §6.3。
