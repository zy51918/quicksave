# QS-0004 跨应用文本分享自动保存（当前状态规范）

> 归档日期：2026-08-18
> 状态：已实现并合入 `main`
> 对应合并提交：`29e7fb0`
> 来源设计：`docs/features/QS-0004/design-share-text.md`

## 当前状态

QuickSave 已支持从其他 Android App 的系统分享面板接收单条纯文本，并自动追加保存到用户配置的目标文件。分享接收流程不展示编辑页面；保存成功或失败后均显示短暂 Toast 并结束接收 Activity，返回原 App。

功能已实现并合入 `main`。当前分支的 JVM 测试、Lint、Debug 构建和 Android 测试源码编译均通过；由于验证环境没有连接 Android 设备，instrumentation 测试尚未实际运行。

## 目标与范围

### 目标

- 让 QuickSave 出现在 Android 文本分享面板中。
- 自动接收并保存 `ACTION_SEND` 的 `text/plain` 文本。
- 保存时复用 DataStore 中当前选中的分类；未选择分类时传入 `null`。
- 复用既有目标文件、SAF 权限、时间戳、分类前缀和文本文件格式。
- 分享成功或失败后返回原 App，不打开 QuickSave 主页面。

### 支持范围

- 单条 `ACTION_SEND`；
- MIME 类型严格为 `text/plain`；
- `Intent.EXTRA_TEXT` 为非空、非纯空白的文本；
- 保留原始空格、换行、网址和代码格式；
- 允许普通单项文本 `ClipData`，但不接受其中包含 Uri 的载荷。

## 非目标

- `ACTION_SEND_MULTIPLE` 或多条文本分享；
- 图片、视频、附件、文件 Uri 或 `EXTRA_STREAM`；
- 仅提供 HTML 而没有纯文本载荷的分享；
- 分享后编辑文本或在分享流程中重新选择分类；
- 新增数据库、网络同步、后台服务或运行时权限；
- 应用内历史记录浏览、检索或修改已保存记录。

## 用户流程与行为

### 成功流程

1. 用户在其他 App 选择文本。
2. 用户在 Android 分享面板中选择 QuickSave。
3. `ShareReceiverActivity` 接收并解析分享 Intent。
4. QuickSave 读取当前选中的分类。
5. 通过现有 `ClipRepository.saveEntry(text, category)` 追加写入目标文件。
6. 显示“已保存” Toast。
7. 结束分享接收 Activity，返回原 App。

### 失败流程

解析失败或保存失败时：

- 显示对应错误 Toast；
- 结束分享接收 Activity；
- 不启动、不导航到 `MainActivity`；
- 不显示编辑页面。

结果文案：

| 场景 | 当前行为 |
|---|---|
| 保存成功 | `已保存` |
| 未配置目标文件 | `尚未设置保存文件` |
| 目标文件不可写 | 保留仓库错误文本：`目标文件无写入权限，请重新选择` |
| 文本为空或仅空白 | `分享内容为空` |
| Action、MIME 或载荷不支持 | `不支持的分享内容` |
| 其他异常无可用消息 | `保存失败` |
| 其他异常有可用消息 | 显示异常消息文本，便于定位文件或系统错误 |

## 技术设计

### Android 入口

`app/src/main/AndroidManifest.xml` 注册：

- Activity：`.share.ShareReceiverActivity`；
- `android:exported="true"`；
- `android:excludeFromRecents="true"`；
- 主题：`@style/Theme.QuickSave.Transparent`；
- Intent filter：`ACTION_SEND`、`DEFAULT`、`text/plain`。

不新增权限、服务或其他应用组件。

### 分享解析器

文件：`app/src/main/java/com/ylib/quicksave/share/ShareContentParser.kt`

解析结果：

- `ShareParseResult.Success(text)`；
- `ShareParseResult.Empty`；
- `ShareParseResult.Unsupported`。

解析条件：

1. Action 必须是 `Intent.ACTION_SEND`；
2. MIME 必须严格是 `text/plain`；
3. `EXTRA_TEXT` 必须存在且 `isBlank()` 为 false；
4. `EXTRA_STREAM` 必须不存在；
5. `ClipData` 不得包含 Uri；
6. `ClipData` 不得包含多于一个 item；
7. 通过后仅调用 `toString()`，不执行 `trim()` 或其他内容变换。

### 保存协调器

文件：`app/src/main/java/com/ylib/quicksave/share/ShareSaveCoordinator.kt`

协调器：

1. 从 `ClipRepository.getSelectedCategory().first()` 读取当前分类；
2. 调用 `ClipRepository.saveEntry(text, category)`；
3. 原样返回仓库 `Result<Unit>`。

既有仓库继续负责目标文件 Uri、写入权限、分类前缀、时间戳和 `FileDataSource` 追加写入。

### Activity 与生命周期

文件：`app/src/main/java/com/ylib/quicksave/share/ShareReceiverActivity.kt`

- Activity 不调用 `setContent`，不展示 Compose 或编辑页面；
- Activity 实例内使用 `handled` 忽略重复 `onNewIntent`；
- 外部 Intent 读取和解析异常进入通用失败提示；
- 通过 `ShareReceiverViewModel` 启动保存任务；
- 使用 `repeatOnLifecycle(Lifecycle.State.STARTED)` 收集保存结果；
- 结果只展示一次，然后 Toast 并 `finish()`。

文件：`app/src/main/java/com/ylib/quicksave/share/ShareReceiverViewModel.kt`

- 使用 `ViewModel` 和 `viewModelScope`；
- 使用 `StateFlow` 表示 `Idle`、`Processing`、`Completed`；
- 第一次 `save(text)` 后设置一次性门闩，后续调用忽略；
- Activity 重建后复用同一个 ViewModel，避免重复追加；
- 完成结果保留在 StateFlow 中，重建后的 Activity 可以继续展示 Toast；
- `CancellationException` 继续抛出，其他保存异常转换为 `Result.failure`。

### 保存格式

沿用既有格式：

- 有分类：`[分类名][yyyy-MM-dd HH:mm:ss] 文本内容`；
- 无分类：`[yyyy-MM-dd HH:mm:ss] 文本内容`。

`EXTRA_TITLE` 等辅助字段不会写入目标文件。

## 数据、配置与兼容性

- 不新增数据库表或 DataStore 字段；
- 继续使用现有目标文件 Uri、分类列表和 selectedCategory；
- 最低 Android 版本：API 29；
- `applicationId` 与 `namespace`：`com.ylib.quicksave`；
- 不新增运行时权限；
- 不影响剪贴板监听、手动输入、悬浮窗和录音功能；
- 旧版本目标文件格式保持兼容，分享记录与已有保存记录使用同一格式。

## 决策记录

1. 使用独立 `ShareReceiverActivity`，避免复用手动输入页造成入口和生命周期耦合；
2. 复用 `ClipRepository`，不新增保存实现和文件格式；
3. 使用 ViewModel/StateFlow 处理 Activity 重建，避免同一分享请求重复写入；
4. 对异常消息保留已有仓库的可读错误文本；仅在异常消息为空时显示通用“保存失败”，以保持目标文件权限错误的可操作性；
5. 归档时以当前代码、测试和配置为准；未把未实际执行的 instrumentation 测试描述为已通过。
